# 🏛️ Уровни системы и ядро

Связано с [[🧠Внутреннее устройство Linux]]

От железа до приложений: кто за что отвечает.

## Уровни системы (сверху вниз)

```
┌─────────────────────────────────────┐
│   Приложения (bash, nginx, firefox)  │   ← то, что ты запускаешь
├─────────────────────────────────────┤
│   Userspace-библиотеки (glibc, ...)   │   ← обёртки над syscall'ами
├─────────────────────────────────────┤
│   System Call Interface (syscall)      │   ← единственная легальная дверь в ядро
├─────────────────────────────────────┤
│   Kernel space (ядро Linux)             │   ← процессы, память, драйверы, FS, сеть
├─────────────────────────────────────┤
│   Железо (CPU, RAM, диск, сетевая карта)│
└─────────────────────────────────────┘
```

Приложение **никогда** не трогает железо напрямую — оно просит ядро через **системные вызовы** (`read`, `write`, `open`, `fork`, `execve`, `socket`...). Ядро — единственный код, у которого есть прямой доступ к железу.

## User space vs Kernel space

- **Kernel space** — код ядра: планировщик процессов, менеджер памяти, драйверы устройств, файловые системы, сетевой стек. Падение здесь = паника ядра (kernel panic), всё виснет.
- **User space** — всё остальное: твой шелл, nginx, Python-скрипт, X11/Wayland-сервер. Падение здесь = просто упал один процесс, система жива.

Разделение держится на аппаратных **privilege rings** (кольцах защиты) процессора:

| Ring | Кто | Доступ |
|---|---|---|
| **Ring 0** | ядро | полный доступ к железу |
| **Ring 1-2** | почти не используются в Linux | — |
| **Ring 3** | user space (твои программы) | только через syscall может попросить ядро |

Попытка пользовательского процесса выполнить привилегированную инструкцию напрямую (например, записать в регистр управления CPU) вызывает исключение, и ядро либо обрабатывает это как системный вызов, либо убивает процесс (segfault/illegal instruction).
