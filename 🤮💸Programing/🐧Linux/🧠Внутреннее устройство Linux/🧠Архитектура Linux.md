# 🧠 Архитектура Linux

Связано: [[🥾Загрузка и init]] · [[⚙️Процессы, память и файловая система]] · [[🔷 Arch Linux Navigation.canvas|🔷 Arch Linux]]

Как Linux устроен по уровням — от железа до твоей команды в терминале.

## Уровни системы (сверху вниз)

```
┌─────────────────────────────────────┐
│   Приложения (bash, nginx, firefox)  │   ← то, что ты запускаешь
├─────────────────────────────────────┤
│   Userspace-библиотеки (glibc, ...)   │   ← обёртки над syscall'ами
├─────────────────────────────────────┤
│   System Call Interface (syscall)      │   ← единственная легальная дверь в ядро
├─────────────────────────────────────┤
│   Kernel space (ядро Linux)             │   ← процессы, память, драйверы, FS, сеть
├─────────────────────────────────────┤
│   Железо (CPU, RAM, диск, сетевая карта)│
└─────────────────────────────────────┘
```

Приложение **никогда** не трогает железо напрямую — оно просит ядро через **системные вызовы** (`read`, `write`, `open`, `fork`, `execve`, `socket`...). Ядро — единственный код, у которого есть прямой доступ к железу.

## User space vs Kernel space

- **Kernel space** — код ядра: планировщик процессов, менеджер памяти, драйверы устройств, файловые системы, сетевой стек. Падение здесь = паника ядра (kernel panic), всё виснет.
- **User space** — всё остальное: твой шелл, nginx, Python-скрипт, X11/Wayland-сервер. Падение здесь = просто упал один процесс, система жива.

Разделение держится на аппаратных **privilege rings** (кольцах защиты) процессора:

| Ring | Кто | Доступ |
|---|---|---|
| **Ring 0** | ядро | полный доступ к железу |
| **Ring 1-2** | почти не используются в Linux | — |
| **Ring 3** | user space (твои программы) | только через syscall может попросить ядро |

Попытка пользовательского процесса выполнить привилегированную инструкцию напрямую (например, записать в регистр управления CPU) вызывает исключение, и ядро либо обрабатывает это как системный вызов, либо убивает процесс (segfault/illegal instruction).

## Системные вызовы — пример

```bash
strace -c ls /tmp        # посчитать, какие syscall'ы и сколько раз вызвал ls
strace ls /tmp             # построчно показать каждый syscall
```

Когда ты пишешь `print("hi")` в Python — где-то в глубине это превращается в syscall `write(1, "hi\n", 3)` — запись в файловый дескриptor 1 (stdout). Терминал, файлы, сокеты, пайпы — для ядра всё это просто файловые дескрипторы, с которыми работают одни и те же `read`/`write`.

## Монолитное ядро (а не микроядро)

Linux — **монолитное ядро**: драйверы, файловые системы, сетевой стек работают в одном адресном пространстве ядра (в отличие от микроядер типа QNX/Minix, где драйверы — отдельные userspace-процессы, общающиеся через IPC). Платится за это чуть большей потенциальной поверхностью для багов в ядре, но взамен — меньше overhead'а на переключения контекста.

При этом Linux гибкий: большая часть функциональности может грузиться/выгружаться на лету как **модули ядра**, не требуя пересборки или перезагрузки всего ядра.

```bash
lsmod                      # какие модули ядра сейчас загружены
modinfo e1000e               # инфа о модуле (например, драйвер сетевой карты)
sudo modprobe nvidia          # загрузить модуль
sudo modprobe -r nvidia        # выгрузить
uname -r                        # версия текущего запущенного ядра
```
