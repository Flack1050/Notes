# 🌐 Networks — основы

Связано: [[🧰DevOps Networking]] · [[🌐Nginx]]

## Модель OSI (7 уровней)

| № | Уровень | Что делает | Примеры |
|---|---|---|---|
| 7 | Application | данные приложения | HTTP, DNS, SSH, FTP |
| 6 | Presentation | кодировка, шифрование | TLS/SSL, сжатие |
| 5 | Session | управление сессией | сокеты, установление/разрыв соединения |
| 4 | Transport | доставка между процессами | TCP, UDP |
| 3 | Network | маршрутизация между сетями | IP, ICMP, роутеры |
| 2 | Data Link | доставка в пределах одной сети | Ethernet, MAC-адреса, свитчи |
| 1 | Physical | биты по кабелю/радио | медь, оптика, Wi-Fi |

На практике в DevOps реально разбираешь **L2-L4 (сеть/транспорт)** и **L7 (приложение)** — средние уровни почти не всплывают явно. Модель **TCP/IP** проще — 4 уровня (Link / Internet / Transport / Application) и именно её реально используют.

## TCP vs UDP

| | TCP | UDP |
|---|---|---|
| Соединение | устанавливается (3-way handshake) | нет, просто шлёшь пакеты |
| Гарантии | доставка, порядок, ретрансляция потерь | никаких гарантий |
| Скорость | медленнее (overhead на надёжность) | быстрее |
| Когда | HTTP, SSH, базы данных — где важна целостность | DNS-запросы, видео/аудио-стрим, игры — где важна скорость |

### TCP 3-way handshake

```
Клиент                    Сервер
  |-------- SYN --------->|
  |<----- SYN-ACK --------|
  |-------- ACK --------->|
  (соединение установлено, можно слать данные)
```

## IP-адресация

- **IPv4**: 32 бита, формат `192.168.1.1`, ~4.3 млрд адресов (давно не хватает → NAT).
- **IPv6**: 128 бит, формат `2001:db8::1`, адресов практически бесконечно, постепенно вытесняет IPv4.

### Приватные диапазоны (не маршрутизируются в интернете)

```
10.0.0.0/8          10.0.0.0 - 10.255.255.255
172.16.0.0/12        172.16.0.0 - 172.31.255.255
192.168.0.0/16        192.168.0.0 - 192.168.255.255
127.0.0.0/8            loopback (localhost)
```

### CIDR и маски подсети

`/24` = маска `255.255.255.0` = первые 24 бита — сеть, последние 8 — хосты (256 адресов, из них 254 пригодны для хостов).

```
192.168.1.0/24   → хосты 192.168.1.1 – 192.168.1.254, broadcast .255
192.168.1.0/28   → всего 16 адресов, хостов 14 (подсети поменьше — меньше "пустых" IP)
```

```bash
ipcalc 192.168.1.0/24       # посчитать сеть/broadcast/диапазон хостов
```

### NAT (Network Address Translation)

Механизм, который позволяет многим устройствам в приватной сети (`192.168.x.x`) ходить в интернет через один публичный IP роутера — он подменяет source IP/port исходящих пакетов и помнит соответствие для обратного трафика.

## Порты

- 0-1023 — **well-known** (нужны root-права чтобы забиндиться): 22 SSH, 80 HTTP, 443 HTTPS, 53 DNS, 5432 PostgreSQL, 3306 MySQL, 6379 Redis.
- 1024-49151 — **registered** (часто используются приложениями: 8080, 3000, 5000...).
- 49152-65535 — **dynamic/ephemeral** — временные порты, которые ОС выдаёт клиенту для исходящих соединений.

```bash
ss -tulnp              # какие порты слушаются и каким процессом
ss -tn state established   # активные TCP-соединения
```

## DNS

Переводит доменные имена в IP. Иерархия: **Root → TLD (.com/.ru) → Authoritative NS (домена)**.

```
1. Браузер спрашивает локальный resolver (обычно у провайдера/роутера)
2. Resolver идёт в root-сервер → "кто отвечает за .com?"
3. Root отвечает адресом TLD-сервера .com
4. TLD-сервер отвечает адресом authoritative NS домена example.com
5. Authoritative NS отдаёт A-запись → реальный IP
6. Resolver кэширует ответ на TTL записи и отдаёт браузеру
```

### Основные типы записей

| Тип | Значение |
|---|---|
| **A** | домен → IPv4 |
| **AAAA** | домен → IPv6 |
| **CNAME** | домен → другой домен (алиас) |
| **MX** | почтовый сервер для домена |
| **TXT** | произвольный текст (часто для верификации, SPF/DKIM) |
| **NS** | какой сервер авторитативен для домена |

```bash
dig example.com              # полный DNS-запрос
dig +short example.com A
nslookup example.com
host example.com
```

## HTTP/HTTPS

- **HTTP** — текстовый протокол поверх TCP (обычно порт 80), методы GET/POST/PUT/DELETE/PATCH, статус-коды (2xx успех, 3xx редирект, 4xx ошибка клиента, 5xx ошибка сервера).
- **HTTPS** = HTTP поверх **TLS** (порт 443) — шифрование + проверка подлинности сервера через сертификат.

### TLS handshake (упрощённо, TLS 1.2)

```
1. Client Hello — клиент: какие шифры/версии TLS поддерживает
2. Server Hello + сертификат — сервер выбирает шифр, присылает сертификат (публичный ключ)
3. Клиент проверяет сертификат (через цепочку CA) → генерирует pre-master secret,
   шифрует публичным ключом сервера, отправляет
4. Обе стороны вычисляют общий симметричный ключ сессии из pre-master secret
5. Дальше весь трафик шифруется этим симметричным ключом (быстрее, чем ассиметрия)
```

TLS 1.3 делает это за меньше round-trip'ов (1-RTT вместо 2-RTT) — заметно быстрее устанавливает соединение.
